# Private ten-bit Kvazaar adapter candidate

This checkpoint adds an opt-in helper library. The exporter and media routes do not use it yet. It does not change the helper license or establish a closed-source release.

The source is Kvazaar 2.3.2, commit `6040962bed5cc68c5ad01234c38c08b8b2822068`. The official tag archive SHA256 is `ddd0038696631ca5368d8e40efee36d2bbb805854b9b1dda8b12ea9b397ea951`. Its public header SHA256 is `fc875992577bdd54eb20cb28057e673293f769246cc8a1d6f0b1d176178df361`. The ordinary eight-bit FFmpeg dependency candidate uses this same pin. Retain the upstream BSD license and notices when packaging this library.

## Build and binding

`ARBIT_BUILD_KVAZAAR10_ADAPTER=ON` adds the excluded targets `arbit-kvazaar10-adapter` and `arbit-kvazaar10-adapter-tests`. Default helper and plugin targets do not link them. The upstream static library and the adapter use `KVZ_BIT_DEPTH=10`; the header stays private. A marker compiled inside that same library returns its compiled depth. Calling `kvz_api_get(10)` alone is insufficient because the upstream implementation ignores the argument.

The archive transformation derives its rename list from every external definition, renames those symbols and all matching internal references to `donut_kvz10_*`, and recreates the archive index. Undefined runtime imports do not enter the rename list. The final census must contain exactly the renamed definitions and no original internal names, including unresolved references. The adapter calls the renamed getter and depth marker. The original library is a build dependency, never a link dependency of the adapter. This permits coexistence with FFmpeg's ordinary eight-bit shared Kvazaar binding.

ELF and MinGW retain the GNU-compatible `nm -P`, `objcopy --redefine-syms` and `ranlib` route. MSVC remains rejected. CMake 3.25 is required only for opt-in because that is upstream's minimum. Turning the adapter off returns before any Kvazaar fetch or tool admission.

The Apple candidate requires a native Apple Silicon host and explicit `CMAKE_OSX_ARCHITECTURES=arm64`. Supply absolute paths through `ARBIT_KVAZAAR10_LLVM_NM`, `ARBIT_KVAZAAR10_LLVM_OBJCOPY` and `ARBIT_KVAZAAR10_LLVM_RANLIB`, plus the matching release in `ARBIT_KVAZAAR10_LLVM_VERSION`. There is no tool discovery or fallback to Apple cctools. Every tool must report exactly the recorded release, which must be 20.1.8 or newer. Configure checks this before fetching Kvazaar; archive transformation checks it again. The Mac dependency-profile owner must provision and record these tools. This change installs nothing and does not change that profile.

Mach-O external C names have an ABI underscore. The mapping preserves it, for example `_kvz_api_get` becomes `_donut_kvz10_kvz_api_get`. A source name already beginning with an underscore retains that underscore after the prefix. The script checks every input and output archive object header for thin arm64 Mach-O, checks the complete renamed definition set, rejects original internal references, and requires unchanged external runtime imports. It writes the mapping and a `.namespace.json` receipt beside the archive. The receipt records tool paths, versions and executable SHA256 hashes, archive hashes, member count, definitions and runtime imports.

LLVM 20.1.8's [pinned Mach-O symbol-map test](https://github.com/llvm/llvm-project/blob/llvmorg-20.1.8/llvm/test/tools/llvm-objcopy/MachO/redefine-symbol.s) covers underscored names with `--redefine-syms`. This establishes the tool operation used by the candidate. Native Apple arm64 Kvazaar archive transformation and coexistence remain unverified until the checks below run on the physical Mac. This checkpoint supplies no production dependency recipe, installer or platform-support claim.

## Encoder ownership and mux contract

One process-wide atomic gate admits one private encoder. Concurrent open fails without blocking. Calls on an admitted object must be serialized by its owner. The encoder closes before configuration destruction; chunks and input/reconstructed picture references are freed before terminal error cleanup releases the gate. Failed initialization and explicit `close()` also release it. `close()` discards delayed frames for cancellation. The caller must remove incomplete output files through the existing exporter cleanup path.

Input is planar YUV420P10LE. Each row uses the AVFrame byte stride and each destination plane uses Kvazaar's pixel stride. The adapter reads little-endian samples explicitly and rejects values above 1023, invalid planes, nonincreasing or absent PTS, and changed dimensions, pixel format or HDR tags. Source and destination strides can differ. The default intra period is 64. Other random-access intra periods must be multiples of the GOP length chosen by the medium preset, matching upstream validation. Width and height must be positive and divisible by eight. This is an admission gate, without rounding, padding or changes to visible dimensions. A future bridge must preserve an existing route or return this explicit error for other even extents until padding and conformance cropping are specified.

`copyCodecParameters()` supplies Main10, visible dimensions, Rec.2020 nonconstant matrix, limited range, left chroma location and PQ or HLG in both codec parameters and padded Annex B parameter sets. The current output contract defines no ST 2086 or content-light fields. The adapter creates no mastering display, MaxCLL or MaxFALL values from `peakNits`.

`encode()` copies the input picture, submits it, and returns at most one mux-ready AVPacket. Its PTS/DTS are the reconstructed picture timestamps; duration is one frame in the reciprocal frame-rate time base. IRAP packets carry the key flag. After submission ends, call with null input until `drained()` is true. A buffered submission without output does not mean end of stream. The existing FFmpeg stream owns timestamp rescale, stream index, packet writing, audio interleave, trailer and output cleanup. This adapter has no container writer.

## Prepared checks and remaining work

The leaf fixture binds a fake ten-bit API and exercises failed configuration/preset/open/headers, returned-chunk cleanup on failure, namespace depth admission, ownership exclusion and reuse, differing source/destination strides, limited PQ/HLG metadata, header padding, multiple delayed packets, exact PTS/DTS and duration, terminal error cleanup, repeated final drain and cancellation. It does not prove the real encoder emits valid HEVC or correct ten-bit pixels.

`kvazaar10_namespace` runs the Python fixtures in `tests/test_kvazaar10_namespace.py`. They cover Mach-O ABI spelling, the full definition map, unchanged runtime imports, GNU spelling compatibility, malformed and wrong-architecture archives, tool release admission, and rejected post-transform drift. These mocked tools do not establish native acceptance.

For the native coexistence check, also set `ARBIT_KVAZAAR10_BUILD_LINK_SMOKE=ON` and supply the ordinary eight-bit profile dylib as the absolute `ARBIT_KVAZAAR10_FFMPEG_KVAZAAR_DYLIB`. Build the excluded `arbit-kvazaar10-link-smoke` target with the approved Mac build/lock route, then run `kvazaar10_macho_link_smoke` through CTest. Do this only from the admitted integrated source. The fixture links the real private archive, adapter, FFmpeg and ordinary Kvazaar dylib. Its inspector independently uses native `lipo` to require thin arm64 inputs, `otool` to require two-level namespaces and the recorded FFmpeg dependency, and LLVM nm to check the getter's supplying-library ordinal in both FFmpeg and the executable. Flat-namespace flags are rejected. The executable uses `dladdr` to require the loaded ordinary Kvazaar and libavcodec files to match the inspected candidates. It requires distinct ordinary/private API bindings and the real ten-bit marker, keeps both encoders open, and encodes and drains one frame through each. One packet per encoder is required. This checks coexistence and real archive linkage; decoded HDR quality and complete exporter behavior need their own fixtures.

Compilation and tests have not run for this checkpoint. The integration owner must admit covering builds from mirrored canonical main, then run the focused fixtures. The archive census runs as a required build step. A later exporter bridge must use the existing FFmpeg mux path and exercise the real library with independently decoded PQ/HLG pixels, bit depth, color tags, visible extent, packet/frame counts, PTS, audio synchronization and cancellation. Reuse `tests/pq_movie_export_runtime_fixture.py` once real jobs and independent oracle inputs are available. Packaging and physical Linux/Windows/Mac acceptance remain separate work.

## Primary sources

- [Kvazaar 2.3.2 API](https://github.com/ultravideo/kvazaar/blob/v2.3.2/src/kvazaar.h) defines compile-time pixel width, strides, encoder ownership and repeated null-input drain.
- [Kvazaar 2.3.2 getter](https://github.com/ultravideo/kvazaar/blob/v2.3.2/src/kvazaar.c) returns the API compiled into the library.
- [Kvazaar 2.3.2 build](https://github.com/ultravideo/kvazaar/blob/v2.3.2/CMakeLists.txt) and [BSD license](https://github.com/ultravideo/kvazaar/blob/v2.3.2/LICENSE) define the pinned dependency.
- [FFmpeg 6.1.6 Kvazaar wrapper](https://github.com/FFmpeg/FFmpeg/blob/n6.1.6/libavcodec/libkvazaar.c) uses the eight-bit API and establishes the Annex B header and AVPacket timestamp/mux contract. The new adapter is independently implemented against the API and does not copy wrapper source.
